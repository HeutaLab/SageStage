# Story map — handoff
_Written 2026-07-31 at the end of a long session, so nothing lives only in a chat._
**State:** the shell is built and in the app (commit `198ea53`). `docs/story-map-design.md` is the
spec and is OUT OF DATE. `.sm-mock.html` is a playable mock and is the AUTHORITY ON BEHAVIOUR.
The next task is folding one into the other: **keep the spec's seams and hazards, take the
mock's decisions.** Do not build faces from the spec as it stands.

## Three decisions that block the fold
Each changes what the spec says, so none of them can be defaulted.

1. **Do child names reach a printed sheet?** The mock prints moments — "wistfully — Amira, at the
   Problem" — on the MAP sheet, which §8 defines as the one that goes home in a book bag. A named
   child's attainment into thirty other families' bags. §11's "no child names" rule covers PACK text
   only and does not cover this; say so in the rewrite, because the two will be confused.
   Options put to Glenn: screen only (recommended) · a per-print choice defaulting off · print the
   words but never the names.

2. **Where does a moment live?** It is evidence for a report written a term later, and every store
   the app has sweeps at 60 days — snapshots (`snapshots.js:42-43, 198-236`) AND `putAux`, which the
   spec nominates (`sweepAux`, `snapshots.js:297-306`). A map untouched over the summer loses its
   moments silently. The only sweep-free per-teacher store is `state.prefs` via `D.setPref`
   (`app.js:264-271`), which competes with live state for the 5MB budget.
   Options put to Glenn: defer moments out of v1 to the assessment suite's evidence pipeline
   (recommended) · state.prefs · putAux and accept the sweep.

3. **The pen.** §12 refused a widget-owned pen; §14.2 gave the reason (`#drawLayer` is screen-fixed
   at z-index 3000, so two pens compete for one pointer stream and give the teacher two Clears with
   different scopes). The mock ships exactly that pen. `modelwrite.js` exports only
   `{ init(deps) }` — every reusable part is private inside a ~1700-line `mount()` closure.
   Options put to Glenn: extract a `window.SagePen` surface from modelwrite — maths helpers plus an
   `attach(svgEl, model, opts)` factory (recommended, touches a shipped widget) · re-implement ~400
   lines and accept two pens that drift · drop the widget pen and accept ink sliding off a scrolling
   face.

## Outstanding blockers from the reconciliation pass
A 5-agent pass over the mock, the spec and the real codebase returned 304 findings and 32
blockers. Twelve were fixed in `198ea53` (see that commit message). These remain:

### 1. The stage gates NOTHING — the lock does — WHY
IMPORTANT for reconciliation: `P.stage` has exactly three consequences in code — it colours the band, it is stamped onto a recorded moment, and the demo button sets it. It does not disable anything. The comment is explicit: 'Two independent things, answering to different people. The STAGE is the lesson's stance. The LOCK is whether the board takes a hand at all, and it is always the teacher's discretion — never the stage's.' Do not wire stage→lock.

_Evidence: .sm-mock.html:646-649, 686-694, 962_

### 2. Typing live-patches the card, never re-renders — WHY
`inp.oninput` writes `b.t` and then hand-patches the selected card's `.btext` textContent and blank classes directly. Comment: 'live-patch the card, never re-render: the caret has to survive every keystroke'. This is a hard constraint on the real implementation — a render-on-input design loses the caret.

_Evidence: .sm-mock.html:773-780_

### 3. Reset does NOT clear moments
CONFLICT TO RESOLVE. Moments carry a child's name and are unambiguously this class's work, but reset-for-a-new-class leaves `P.moments` untouched — so the next class inherits the last class's named moments, and they still print on the map sheet. Either moments must be cleared by reset, or they must be lifted out of the map into the evidence store (which is where the assessment-suite direction points).

_Evidence: .sm-mock.html:1550-1556 vs 956-963, 1687-1696_

### 4. storyLine() vs 'first visible actual' — two different references in use
CONFLICT TO RESOLVE. Counterpoint uses `storyLine()` = first non-target track REGARDLESS of on/off (deliberate, documented). But the word bank's 'want' ring, `gapOf()` and the gap ribbon all use `P.tracks.filter(t=>t.on && t.kind!=='target')[0]` = first VISIBLE actual. With the seed data these coincide; with a hidden first line they diverge. Decide per feature and document it — the counterpoint reference must stay fixed, the gap reference probably should follow what is on the board.
