   `click-assessment-2026-07-31.md` §F — committed **1 Aug** — asks for a fresh

   What is left to decide is really just: *does §F stand, or is it superseded?*
   **Three things now hang off it that did not before:**
   - **The CSP added on the 2nd ships *inside* the bundle and is enforced on top
     of the Tauri config.** `copy-dist.sh` copies `index.html` verbatim into
     `dist/` and `frontendDist` points at it, and a browser applies every policy
     it is handed — the intersection wins. Found by fact-check on the 3rd:
     the meta's `connect-src` omitted `ipc:` / `http://ipc.localhost`, which is
     how Tauri v2 reaches Rust, so the bundled app would have lost **the whole

     **keep the two policies in step directive by directive**, and the first
     bundled boot is where you find out you didn't.

     has only ever been asked under `http://localhost`. Under Tauri the webview
     reports something else, and if that comparison goes wrong **every embed
     silently gets the sandbox escape back**.
   - The export memory item may be *critical* rather than major on WKWebView
     (§4), and `@media print` is worth nothing at all if the answer is desktop.
   Browser means 11–12 Aug stays calm and P3 stays out of scope. Desktop means
   both come back, plus the three above.
2. **The annotation eraser.** Erasing is composited `destination-out` with the
   eraser stroke *stored*, so draw-then-erase only ever adds data. Making it
   shrink means geometric stroke splitting, or dropping only the pen strokes an
   eraser fully covers and accepting that partial erasure still grows, or
   rasterising and losing vector editing. A judgement about what a teacher loses.
3. **The storage eviction path.** What gets thrown away when a board is full —
   oldest ink? largest images? ask them? The measured size readout and headroom
   probe already ship; this is the policy, not the plumbing.
4. **Poll vote (≈28px) and name-chip-× (18×18)** — the same "too small" question

5. **Is the browser build a supported print surface?** `print.js` builds its own

   What is missing is `@media print`, which only matters when a teacher hits
   `Cmd+P` out of habit in a browser. If the testers run desktop, close it.
6. **Widget geometry on a smaller display.** Today's clamp persists once the
   teacher interacts. The 0×0 bug found on the 3rd came out of this same design,

### The export 🟠 — re-scoped upward on 3 Aug, and possibly critical

The earlier scoping still holds as far as it goes: `export.js` fills `shots[]`
with every screen's canvas before any writer runs, the writers *do* release as
they consume, so the peak is at the end of the render loop. All three writers
need only a raster plus dimensions and the format is known before rendering
starts, so each screen can be rasterised and released immediately.

**Three things triage added that change the job:**

1. **The ceiling is 120 screens, not 30.** Nothing caps deck size, "Export deck…"
   selects all, and the pptx importer permits 120 per file. The honest worst case
   is ~3.7 GiB, not ~1 GB.
2. **Fixing `shots[]` does not remove the peak.** `writePngs` and `writePptx`
   accumulate ArrayBuffers and structured-clone them to the worker *without*
   transfer — deliberately, so the buffers survive for the fallback path. Once
   the canvas peak goes, that doubling is the dominant term. Keeping `Blob`s
   instead removes it *and* keeps the fallback, since Blob clone is by reference.
3. **On the shipping target it may not crash at all.** WebKit discards canvas
   backing stores rather than throwing, and nothing in `export.js` checks a
   raster for emptiness — so the plausible WKWebView outcome is that **some pages
   export blank, with no warning**. That is silent corruption of children's work.
   **Check this first**: if it holds, the item is 🔴 and its priority changes.

A cheap interim exists if the full refactor slips: clamp the scale factor as a
function of screen count, or warn in the dialog above ~25 screens. A few lines,
and it does not touch the writers.

Still not done for the original reason — a memory fix nobody has watched a real
30-screen export survive is a claim, not a fix.

## 5. Known limitations in what shipped

State these plainly rather than discovering them later.

- **Nothing from any session is tested on Tauri.** Storage and cross-tab (the
  close-time flush, `hasPending()`, the adopt path), and now the P0 security work
  and everything in P5/P6. Two pieces depend on the webview specifically: the CSP
  ships inside the bundle (see decision 1), and **two independent guards, not
  one, need a Tauri pass**:
  - `sameOrigin()` / `frameSandbox()` decides `allow-same-origin` for the **embed
    and video** iframes. That one comparison is the whole escape guard *for those
    two*.
  - The **document** widget never calls it. A remote document is hardcoded to
    `sandbox="allow-scripts"`; a **local file gets no sandbox attribute at all**,
    and its `blob:` URL genuinely is same-origin with the app. What protects that
    path is a different mechanism entirely — the retype at pick time in
    `setSessionFile()` (`file.slice(0, size, 'application/pdf')`). If the retype
    does not hold on WKWebView, the P0 hole reopens on the shipping target.
- **Performance work has not been near a weak school GPU** — the hardware the
  whole P5 block is named for. The changes are fewer operations by construction,
  not by profile.
- **Three P5/P6 fixes are verified by reasoning, not measurement.** The clock's
  reallocation count and the mats' resize coalescing were not measured in situ —
  several attempts to drive those repaint paths synthetically never reached them.
  The draw-pad listener count could not be driven from an automated pass either.
  All three still render and behave correctly; the claim that they are *cheaper*
  rests on the code.
- **`pickImage` cannot be tested end to end** — the OS file picker is not
  scriptable. The failure path was verified by transcribing the function into a
  harness and feeding it a truncated JPEG, a real HEIC and a zero-byte PNG.
- **The multi-tab conflict is unresolved by design, not fixed.** When both tabs
  edit at once one edit is lost; it now loses the *right* one. Converging both
  needs per-field merging with timestamps, which does not exist here.
- **Focus is not preserved across a rebuild that genuinely is needed**, and
  dashboard list add/remove still drops input focus on its full re-render.
- **Export is verified at the mechanism level only.** The blob Worker starts
  under the new CSP and `importScripts` loads JSZip. A real 30-screen export has
  still never been watched — see §4, and check the WebKit blanking question
  before anything else.

## 6. Working notes for whoever picks this up

**The checklist is a set of leads, not a set of defects.** This is the single
most load-bearing sentence in the document and three days have only sharpened it.
Findings have turned out already fixed, or wrong about their own cause, or
asking for something that shipped later in a better form — in P0, P1, P5 and P6.
The EXIF third of the `pickImage` item was worse than stale: **implementing it
would have caused the bug it describes**, because browsers already honour EXIF
and adding rotation double-rotates every portrait photo. Line numbers have
drifted by hundreds of lines and must not be trusted; find code by identifier.

**Weight your scepticism by direction.** "Already fixed" is the dangerous
verdict — a wrong one ticks a real defect off and ships it. "Still broken" only
costs someone time. On the 3rd, a first pass closed the draw-pad paper item as
stale; a second pass measured the output pixel row by pixel row and found the
paper drawn in the wrong place on six families. Check the closes hardest.

**A passing test can pass for the wrong reason.** Twice in two days:
- A blob-retype check passed on the fixed path *and* on the unfixed control,
  because the CSP was catching the payload before the retype mattered. Isolating
  it needed `blob.type`, not script execution.
- A chime test reported zero oscillators and looked like a clean failure; the
  instrumentation had gone on after the timer already fired.
Confirm the *mechanism*, not the absence of the symptom.

**A catch that turns every throw into "the data is bad" will eventually turn a
bug in your validator into data loss.** `load()` wraps `normalize()` in a
try/catch whose job is to quarantine unreadable state. A temporal-dead-zone
`ReferenceError` in a new validation pass therefore quarantined four real decks
and reset the app. They came back from the quarantine copy — which is yesterday's
salvage fix earning its keep the morning after it shipped.

**Fingerprint the state before you start. It is not paperwork, it is the
restore.** Both recoveries this week — the quarantine and the nine widgets
collapsed to (-60, 0) — were only possible because deck ids, widget ids and
coordinates had been recorded at session start. `kmbg4hzt` at 78.33984375 is the
canary.

**Test on a different origin.** `127.0.0.1` and `localhost` are the same server
and the same files but *different* `localStorage`. A suite that rewrites state
twelve times cannot touch the real decks. This should have been habit from
session one.

**Two older ones that still hold.** Back up state in the tab you are *not*
writing to. And widget ids and coordinates settle questions that deck-level
counts cannot — a count that looks wrong is usually a debounced write landing
between two reads.

**Test fixtures need a real screen shape.** Hand-built screens missing a
`background` used to crash `applyBackground`; `normalizeScreen` now repairs that,
but clone an existing screen anyway.

**Verifying is where the time goes, not editing.** Unchanged, and if anything
understated.
